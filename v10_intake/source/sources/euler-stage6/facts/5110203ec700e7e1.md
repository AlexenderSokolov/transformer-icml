Binary long division processes all numerator bits. Its invariant after each prefix is processed_prefix=divisor*quotient+remainder with 0<=remainder<divisor. Double the remainder, insert the next bit, compare with the positive divisor, and perform a gated subtraction and quotient-bit write. Full sweeps and rewinds cost O(w) per bit, hence O(w^2), with exact quotient and remainder. Zero/leading bits do not terminate routines early.

Public delimited word lengths and a fixed number of bit passes implement these operations on a constant number of tapes without a random-address lookup or a per-bit address oracle. Fixed-size buffers may be reused after charged clearing. Complete products of the semantic inputs, doubled remainders and scratch stay within the constant-width slots.

A binomial query therefore costs at most K multiply/divide pairs, O(Kw^2), with O(Kw) checks/copies already included. Padded inactive rounds use safe factor/divisor one. If k=0, all rounds are inactive and the answer is one; if n<k, all active computations are suppressed and the final answer is zero. Equal-duration guarded arithmetic handles both. A single rank/unrank, with the query count of Section 4, costs
    O(K^2(r+B+1)w^2).                              (20)
No loop enumerates H candidates or the composition set.

## 10. Two sequential table scans, dynamic writeback, and normalized boundaries

Store the fixed row fields contiguously in public row-major order; the two endpoint fields may be on a separate fixed tape region. Their conceptual concatenation is the message in (1). No variable addresses are stored in table fields.

Here is a concrete two-scan departure routine. The first data scan runs from the left end of the rank table to its right end. Public row counters enumerate all K^2 labels. Compare each row label to the saved endpoint pair, and copy/gate its L-bit field into the selected-rank buffer if equal; otherwise preserve that buffer. The buffer head traverses and returns across its fixed L-bit region each row, paying O(L) work per field. Each public comparison and counter update costs at most O(w). Thus the first scan, including buffer movements, costs O(K^2 L+K^2 w).

The table head now stays at its public right-end location while the selected row is decoded. Apply the Section 2 update using the spare coordinate, and re-encode. Selection of the incremented label uses a full K-coordinate buffer scan and B-bit label comparisons; even a conservative O(Kw^2) local charge is absorbed by (20). Compute both possibilities with a gated increment/decrement, so spare-zero and spare-positive cases have the same schedule. Unrank uses exactly K coordinate rounds with exactly t_search bisection iterations each, and every binomial call uses exactly K arithmetic rounds. Ranking also performs its fixed K coordinate rounds. Small sums or already frozen rows do not shorten the routine.

The second data scan traverses the table from right to left, enumerating the public row order in reverse. At each field, either write the new rank in reverse bit order if the row matches, or retain/rewrite the old bits if it does not. The rank-buffer head is correspondingly placed at a public end and traversed/reset on every field, whether selected or not. Full gated writing costs O(L) per field and public comparisons cost O(w). The table head ends at its public left origin. This uses two full table data scans, not K^2 row decodes; any associated buffer/head resets are included in the same linear scan bound. Endpoint storage has constant fixed-length sweeps in addition.

Update the endpoints by a fixed copy of the second label into the first and the new label into the second. Clear the input buffer, saved old endpoints, selected-rank copies, expanded K+1 coordinates, spare/branch flags, binomial and arithmetic scratch, all remainders and transient addresses. Restore every work head to a public origin and reset control/loop fields; the public boundary index j alone need not be zeroed. At the next input boundary the only nonpublic contents are the rank table and the two endpoints.

Every loop above has a public length determined by K,M,h,r. Arithmetic uses full padded word widths, including inactive cases; bisection freezes rather than exits once the interval has length one. Endpoints or capacity exhaustion change gated values, not the schedule. Initialization, row selection and reverse traversal are also fixed-duration. Hence each boundary's elapsed work is a public function of j and the public parameters. Head positions, addresses and timing cannot encode additional history. The first two input stages have their own fixed public durations. The source-independent fixed global schedule is consistent with reading the next symbol only when its observation is allowed.

Invalid selected ranks are replaced by safe rank zero before the fixed update work; invalidity scratch is then cleared. For genuine histories, induction guarantees every field remains valid, including updates crossing H. One can check validity while copying a selected rank, with O(w) extra work, within the bounds above. The final readout scans the whole table in fixed public order for row Y_M, decodes only that row, computes t either as H minus spare or by a full sum, and performs the exact K-1 output divisions and residual. It may use fixed delta_0 fallback on an invalid selected rank. Its final source-dependent scratch is a function of the permitted final boundary state and is physically charged.

The one-hot input is scanned once when each symbol is acquired, using a public index and gated B-bit conversion. Later routines use only its converted label and clear copies. Earlier symbols survive only as the two allowed endpoints until shifted out; no raw prefix is retained. The computational instruction may read that bounded label scratch while processing its symbol; it does not request the original input again.

## 11. Full online work, physical peak, offline format, and batch convention

One-hot acquisition costs NK bit operations and conversion costs O(NKB). Every departure uses two full table scans with work
    O(s_cap+K^2 w),                                (21)
one rank/unrank with (20), local row updates, endpoint copying and scratch clearing. Since L<=K(2r+10)<=w, s_cap=O(K^2 w), and (21) is absorbed by (20). Clearing the K+1-word buffer and constant scratch costs O(Kw), also absorbed. There are exactly M departures.

The final row selection, one unrank and dyadic readout cost at most one more term (20), plus O(Kw^2) for complete divisions/output. Since M>=2 this fits the M multiple. The first two input stages, initial table allocation/zeroing O(P), public C_tot generation if also performed online, and all fixed reset/padding costs fit the same bound. In particular P=O(K^2 w+Kw) and is dominated by K^2(r+B+1)w^2. Because N=M+2<=2M and w>=B, O(NKB) is also absorbed. The complete online work is therefore
    O(NK+M K^2(r+B+1)w^2).                         (22)
All M updates are genuine online work; data-dependent rank computations have not been moved to offline generation.

The simultaneous physical storage at any phase is the sum of:
- the K^2 L-bit rank table and endpoint fields, with constant overhead for fixed delimiters;
- any constant number of temporary table/message copies actually used (the two-scan implementation need not duplicate the whole table);
- one expanded row of K+1 O(w)-bit slots, its current data/output buffers, O((K+1)w) in total up to a fixed factor;
- a constant number of complete-product, quotient, remainder, guard and rank words, O(w);
- public K,M,h,r, derived constants, global input counter, public row/coordinate counters, head/layout descriptions and the compact finite microprogram, O(w) plus fixed delimiters;
- the current one-hot buffer, O(K), and bounded endpoint/label copies, which are absorbed by the preceding terms.

Any simultaneously live old/new copy in a sweep is included as a constant multiplicative factor. Both table and expanded row are alive during updates; the peak includes both. There is no K^3 b-bit full-count bank at any phase. Summing first and then taking the maximum over phases gives streaming phase-total physical peak
    O(P), P=s_cap+(K+1)w+w.                        (23)
Erased scratch continues to have its allocated physical size; clearing only removes history dependence. Thus (23) concerns the whole computation, whereas s_cap concerns normalized boundaries.

For a concrete compact full format, serialize a fixed finite-state microprogram, binary public and derived parameters, fixed layout/delimiter descriptions, and initialized zero-filled table, work and output layouts. The all-zero rank bank represents the correct empty counts by Section 2. No H-bit unary row, all-composition codebook, per-data random address table, or unrolled instruction enumeration is included. The full length, including all initialized cells and program/metadata, is O(P+w).

Generation computes C_tot with O(Kw^2) work and O(w) scratch. Since P>=(K+1)w, this is bounded by O((P+1)(w+1)). All actual full-format output writes, public layout loops, position/control operations and zero fills can be charged conservatively at O(w) per emitted bit. Thus
    offline generation/full writes O((P+1)(w+1)),
    offline phase-total physical peak O(P+w).      (24)
If generator output and runtime image coexist, both are included in the simultaneous sum. Initializing a layout online instead of serializing it does not make its O(P) writes free; (22) includes them. A separately chosen fully unrolled instruction format would need to pay its expanded length and construction, and is not silently assigned the compact costs (24).

If the input convention provides a full one-hot batch buffer at the beginning, add its NK bits in every phase where it remains allocated. The resulting physical peak is O(NK+P), not O(P). Acquisition, clearing/erasure or disconnecting consumed prefix cells, and the sequential access moves cost O(NK) and are charged. Future cells must be inaccessible before their prescribed observation times, and consumed input must not be readable by the algorithm after its processing or across the late-query cut. A streaming input adapter achieves the original one-read interface. The existence of the optional batch allocation is not erased from the bill. Read-only retained raw history accessible to the decoder would constitute a different model.

The costs above are analytic finite-program construction bounds. No literal tape execution, instruction ledger, emitter/compiler run or hardware measurement is claimed. Stationary tape persistence is storage, not free neural layerwise holds; bit-tape space is not shared-token neural width. Expanding this program into a neural execution would require its own routing, holds, shared-token and full-sequence cost proof.

## 12. Minimum sufficient configuration and the whole streaming peak

Set, for 0<tau<1,
    M_tau=max(2,ceil((128K^(5/2)/tau)^2)-1),
    h=h0(M_tau), r=max(1,ceil(log2(1/tau))),
    S=K^5/tau^2,
    z=log2(1/tau), Lambda=1+log2 K+z.
Then N=M_tau+2=O(S), h,b=O(Lambda), r<=z+1, and B=O(1+log2 K). Equation (19) gives
    w=O(K Lambda).

For the sharper peak, it is important not to replace every term by K^3 Lambda. Use (4) and expand the row-scratch contribution instead:
    s_cap=O(K^3(1+z)),
    (K+2)w=O(K(h+b)+K^2(r+B+1)).
Since B<=K and log2 K<=K for K>=2,
    K(h+b)+K^2(r+B+1)
       =O(K(1+log2 K+z)+K^2(1+z)+K^2 B)
       =O(K^3(1+z)).
Combining these terms proves
    P=O(K^3(1+log2(1/tau))).                      (25)
This includes program/public parameters, the one expanded row, arithmetic scratch and final high-precision output, as well as the entire online rank table. It is the whole streaming physical peak at the stated minimum-sample h0 configuration. For arbitrary larger M or h, the b and h terms in the original P remain and are not claimed to disappear.

Substitution into (22)--(24) gives the requested conservative bounds
    online O(S K^4 Lambda^3),
    offline O(K^4(1+log2(1/tau)) Lambda),
    optional batch peak O(SK+K^3(1+log2(1/tau))).   (26)
These do not assert optimal computational work. They all describe this one implementation rather than combining the time of another algorithm with its packed space.

If tau=a0/b0 is supplied as a positive rational in (0,1), preliminary public configuration is computed by integer comparisons: choose the least r>=1 with 2^r a0>=b0, and compute
    M_tau=max(2,ceil(2^14 K^5 b0^2/a0^2)-1).
The ceiling is obtained from exact quotient and remainder. Then obtain h0 and lengths by binary scans. For total rational-input length ell_tau, a conservative additional cost is O((ell_tau+B+16)^2) work and O(ell_tau+B+16) physical bits, including input and configuration-output encoding. The shift/comparison search has at most ell_tau+1 rounds, and all operands have O(ell_tau+B+16) bits; the fixed number of products and one division have the stated squared bitwork. This public-configuration phase is additional to the codec on integers K,M,h,r. A redundant huge rational description is not free and, if retained simultaneously, its storage is added to the phase sum. The streaming peak (25) is for the configured streaming program, not an uncharged arbitrarily long tau-input buffer.

Within the small-tau domain of Section 8, the cut lower requires the stated order of history-dependent capacity, while (25) supplies a same-order all-phase streaming peak in the explicitly declared bit representation and configuration. This does not establish a representation-independent exact physical-space lower bound for every imaginable machine.

## 13. Boundary closure and evidence scope

All statements STATE/CAP, MAX-H/RISK and the general COST hold for every K>=2,M>=2,r>=1 and legal h. They cover J=0, J=H, H>M, spare zero, visits crossing H on the last two updates, two identical late departure rows/labels, the empty M=2 prefix count table, arbitrary initialization, zero edges and reducible, periodic or transient sources. The auxiliary fixed row stacks are purely for proof; neither their size nor their content is algorithmic information.

The additional LOWER and constant-factor boundary match are only claimed for K>=12,tau<2^-16 and M satisfying SUFF, inherited without extension from 018. The sharper full physical peak is tied to the explicitly stated minimum-SUFF, h0 configuration and its full cost ledger; general parameters retain P.

The complete proof uses exactly the two listed admitted predecessors. Lower bounds and necessary samples have not been merged into a common witness, and no older Fact acquires 019 as a reverse prerequisite. Normal independent acceptance is required before reporting this new conjunction as admitted. The root is not reopened.

This remains a sequential streaming-bit implementation, not the SRC shared causal batch neural program. It does not exclude allowed-reread strong direct predictors or prove any universal Transformer resource optimality. True same-neural-budget allocation, general-K fault sharpness, physical correction/injection and literature novelty remain separate work. Truncation, finite composition coding, bounded differences and log-sum concentration are standard methods, not new tools or priority claims.
