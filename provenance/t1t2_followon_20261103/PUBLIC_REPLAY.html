2. 数值记录到底检查什么

新记录检查器只读取三份 JSONL，共1,106条顶层保存记录：90条 population、8条 reverse-moment 和1,008条 no-BOS case summary。详细字段/覆盖/安全报告说明严格类型、规范有理数、有界长度、保存输入顺序指纹、部分保存值关系与范围检查。它不重建 J/C、lag-copy、gate、网络、Markov 矩或任何完整科学输出。完整字节校验负责拒绝未被字段关系覆盖的有效形状改动。

no-BOS 数据覆盖 N=3,…,8、η=1/4或1/32 的所有二进制词。原记录有标量 b/c、完整词、末对、J/C、最大 copy error、整体 gate-exact 标志、精确最终 output/add-one/error/bound 和 pass 标志，但没有逐位置或逐边 Q/K/V、logits、attention weights、gate preactivation/hinge、逐 token gate 数组或逐 head 端口数组。保存标量预算不是保存完整 logit trace。不可省略的原始保存澄清保留这个限制。

原1,008例脚本实现的是理想2ᵏ权重的专用近似指数后端，不是泛用浮点 exp，也不是 dyadic logit 的精确真实 softmax。上述有限诊断不证明一般逐路径界、复杂度账本或新颖性。以后另做完整 trace 运行也必须单独标注为新记录，不能称为原始运行恢复；本次没有新运行。

4. 不要把历史生成器当作默认入口

历史脚本留档便于检查研究方法，但其中部分使用固定输出名，直接执行可能重写现存日志或生成新科学输出。发布核验没有执行它们。只有新只读检查器是默认入口。随附软件单元测试会在新的临时目录复制保存样本并作确定性损坏测试；那是检查器测试，不是研究实验或原始运行重放。

若另行复算，须先人工核对公开副本、输出路径和历史原始绑定；使用隔离副本、全新输出目录，并依据独立审阅后的记录协议保留每个必要值。被规范化报告的哈希必须按映射显式处理，不能静默弱化校验。新的结果应记录为新的运行；本交付未实施该操作。用户行政输入、第三方全文和旧私有材料不随档案提供，不应声称这些输入已恢复或旧流程全部可原样运行。
