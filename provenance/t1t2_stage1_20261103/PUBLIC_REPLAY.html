1. 安全的默认核验

使用可信的完整 Git 仓库检出和 POSIX Python 3.10+。先确认检出对应预期公开提交。仓库原有 tools/public_verify.py 检查全库存的成员、长度和 SHA-256；工作流不改动。下列新入口检查本阶段和九个明确继承的公开文件，并对 14 个数值文件的 58,048 条现存记录作有限一致性检查。

在仓库根目录执行。清单的信任锚来自已经核验的仓库库存或外部发布记录，不能把任意待审文件自己计算的哈希当作独立可信的期望值。库存自引用文件被原有规则排除；阶段清单不包含自身或全局库存，其自身身份由全局库存和 Git 提交绑定。

python -I -B tools/public_verify.py
MANIFEST_SHA=$(python -I -B -c 'import json; d=json.load(open("provenance/PUBLIC_INVENTORY.json")); print(next(r["sha256"] for r in d["files"] if r["path"]=="provenance/t1t2_stage1_20261103/STAGE_FILE_MANIFEST.json"))')
python -I -B provenance/t1t2_stage1_20261103/verify_public_archive.py "$PWD" --manifest-sha256 "$MANIFEST_SHA"
python -I -B -O provenance/t1t2_stage1_20261103/verify_public_archive.py "$PWD" --manifest-sha256 "$MANIFEST_SHA"

检查器只向标准输出报告，不写回文件。请不要用输出重定向覆盖档案中的历史日志。单独的数值检查器为 verify_retained_records.py；它不替代外层完整字节核验。检查范围及测试报告说明哪些保存字段被核查、哪些量不重算。随附单元测试只使用已保存样本与人工损坏夹具，并在新临时目录写测试文件，不是生产只读入口。

3. 不要直接把旧脚本当默认重放入口

历史脚本为完整留档而保存，其原命令可能写固定相对输出、依赖未分发的文献全文，或重建先前已有的枚举记录。默认检查不会调用它们；本次发布准备也没有运行这些旧程序。尤其报告构建器的历史输入哈希或输出位置不是本次公开版本的自动构建契约。

若另行研究性执行，应先人工读源码和绑定，使用独立副本和全新输出目录，不覆盖任何原件或把后生成输出冒充原始记录。公开副本已隐私规范化时，只能在独立副本中依据映射明确调整输入绑定，记录修改与输出身份；不能悄悄跳过校验，也不能宣称恢复了已排除的原始内容。所需第三方全文请从原论文链接依法自行获取，不得把未获取输入说成已复现。这里没有提供或运行这种历史生成重放。

4. 有限检查的实际含义

  • 58,048 是14个已保存文件中的记录计数，包含保留在不同来源路径的相同证据，不表示同样多的独立研究案例。992 个刻意重复的样条输入对按原记录保留，不能简单去重。
  • 验证器核查类型、有界规范有理数、已有输入键顺序指纹、保存的计数/概率和、若干比率/误差/界关系。它不生成新词、不重算全模型、网络或路径搜索，也不把有限算术结果提升为普遍定理。
  • 稀有族 v1 日志曾错记600，后纠正为624；两份各含624条内嵌路径记录的文件按各自来源保留（每份16条顶层 JSONL 记录）。受限端口细化记录的7,290个派生子情形并非另一个独立保存数据集。
  • 错误谓词的旧 Route B 记录是弃用历史。正确重放记录不会使原搜索日志变为已保存，也不会反向证明错误版本正确。
