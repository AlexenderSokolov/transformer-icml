# Fixed seven-unit increment: privacy and source audit

## Release scope

The explicit allowlist contains 100 files: 554,095 original bytes and 553,598 declared public-export bytes. It covers AB003, JB001, BK001, BK002, KA001, CB001 and CB002, together with their proof/review/diagnostic records, authentic revision and snapshot history, direct source bindings, and the separately adopted BK002 all-sixteen-position clarification. The existing initial publication tree was not modified.

The seven accepted proofs and all eight authoritative acceptance/adoption receipts remain byte-identical. Six of the seven accepted review files are also unchanged. CB001's review changes only the nonmathematical reviewer-attribution phrase in its header; its accepted original hash remains recorded and its public hash is separately declared.

Twenty-eight files belonging to later KH001, KH002 or CB003 research are explicitly outside this increment. No recursive archive, cache, original user prompt, unrelated source tree, third-party full text or later literature dossier is included. Mentions of later work inside authentic historical documents do not import those later units or make them premises.

## Privacy decisions

There are ten exact line replacements across ten files. They remove non-scientific publication/contact action reports, the private execution-error and duplicate-reviewer anecdote in the CB002 handoff, and private orchestration wording. The two BK001 reconstruction disclosures still state clearly that the old bytes were not backed up contemporaneously and were reconstructed from the documented single-paragraph edit. The actual scientific failure and correction records remain intact.

No raw redacted values are included in the export plan. Each edit has its source-line hash and safe replacement; every file has its original and public-export SHA-256. The source scanner found no matching credential, personal-contact, absolute personal path, private routing identifier or original-prompt pattern in the fixed allowlist. A broader operational-prose inspection identified the ten edits above. A zero pattern result is not a guarantee against arbitrary unknown secrets.

Mathematical uses of private randomness, finite token execution, source parameters and decoder capacity are not private operational telemetry and are retained. Source IDs, receipt hashes, actual review verdicts, the BK001 reconstruction warning, and the genuine BK002 and CB001 correction histories are scientific provenance, not material to erase.

## Source closure and integrity

The structured source audit verifies 300 bindings resolving to 125 unique paths, with no missing source or mismatching original hash. Forty-eight inherited paths are already present in the initial public tree and are reused rather than overwritten. Five inherited review exports differ from their original source bytes; every original/export pair matches the existing declared public source map, including its inherited stage-eight records.

Historical receipts, manifests and scripts retain their original expected hashes. The public source map must add the ten new original/export pairs. A reconciliation may apply only after verifying the exact declared public hash for that exact path; it must not skip integrity checks, invent originals, silently alter historical expected hashes, or treat any unlisted change as equivalent. The existing inherited privacy maps remain authoritative.

The BK002 all-sixteen clarification is additive. It corrects a prose omission of matrix position (00,10) and the old arithmetic count, while retaining the originally accepted matrix, inequalities, theorem domain, constants, proof/review bytes and diagnostic records. It is not a new theorem or a rate revision.

## Checks performed and limits

- All 100 original file hashes and all computed export hashes were checked.
- All seven acceptance proof/review bindings and the separate clarification adoption binding match original sources.
- All 38 JSON files parse.
- All 20 Python programs parse and are byte-identical to their originals.
- All 713 indented Markdown lines and both fenced blocks are unchanged; all accepted proof files remain byte-identical.
- Exact source closure has no unresolved binding.
- The final public preview has zero targeted private-routing, credential, prompt or execution-telemetry markers.
- The BK001 endpoint-bound diff and both CB001 correction/review diff bodies exactly match their retained before/after texts.

These are source, privacy and preservation checks, not a new mathematical certification. This audit did not run the scientific diagnostic programs, rebuild manuscripts, publish to GitHub, or verify any remote commit. Scripts that write diagnostics or regenerate bindings should be run only in a disposable verification copy, with explicitly declared source-hash reconciliation where required.
