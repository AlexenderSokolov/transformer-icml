# Terminal KL: public export and verification boundary

This is a privacy-screened public derivative, not the complete original sealed package. Historical reviews bind the original source hashes; export integrity verification is separate. The original local research files were not changed.

## What is included

- The stationary normalized-logarithm proof, two exact-source mathematical reviews, its literature audit and separate exact-real/finite-bit output corollaries.
- The arbitrary-initial-pair fixed-alphabet logarithmic-rate proof, both analytical reviews, predecessor log-squared proof, HJW lower-bound applicability audit and output corollaries.
- Bundled exact-real construction and specified integer/dyadic evaluator proofs and reviews in each package's `sources/` and `reviews/` folders.
- Three direct stationary predecessor files, preserving the earlier result and the limits of its row-tilt argument.
- Historical source-binding ledgers, final-file reviews, HTML verification reports and preparation scripts, explicitly retaining their original scientific identities and limited scope.

Private operational records and their aggregate inventories are excluded. No credentials, unrelated personal data, original user messages, copyrighted article PDFs, missing training records, or reconstructed training outputs are included.

## Original versus public identities

`PUBLIC_SOURCE_MAP.json` records each exported file's original and public SHA-256, size, Git blob identity and byte-identity flag. For edited files it supplies exact original/public line ranges, segment hashes and only the public replacement text. Removed values are not reproduced.

Edits remove nonmathematical preparation locators and unavailable sibling-source locators, correct an inherited unavailable-local-copy statement to its verified public GitHub source, shorten environment-specific presentation failure details while preserving the unverified-rendering limitation, and add public-export notices. Mathematical claims, formulas, assumptions, constants, review objections, historical status labels and original expected hashes are not rewritten. The public DOI is a bibliographic locator, not a promise that its download is byte-identical to the originally inspected published PDF.

The original stationary seal was checked before export: 25/25 entries, 420264 bytes, all hashes and sizes matched; seal SHA-256 `1e99672c4695cabdddff34bd8f435cc02060f8a4007851fc620ed185a5255faf`. The original fixed-alphabet ledger had 22/22 entries and 375765 bytes matching its JSON and SHA256 ledgers. These counts describe the original preparations, not the public member set. Their public subset and current identities are determined only by the public source map and repository-wide `provenance/PUBLIC_INVENTORY.json`.

Original `SOURCE_BINDINGS.json`, `MANIFEST.json`, `MANIFEST.sha256`, `FINAL_ARTIFACT.json`, `HTML_VERIFICATION.json` and final-file reviews remain historical evidence. Their hashes must not be silently replaced with exported hashes. Historical final-file reviews do not claim to have reviewed the later sanitized HTML bytes. Review reports are independent LLM-assisted analytical checks, not external peer review or formal verification.

## Safe verification and reproduction limits

From a complete repository checkout, run `python3 tools/public_verify.py`, then `python3 -m unittest discover -s tests -v`. The existing checks validate exact public membership and byte hashes and exercise the verifier's rejection cases. They do not prove the mathematics, rerun training, certify numerical software, or visually render the HTML.

The retained `build_html.py`, `check_html.py` and `write_manifest.py` scripts are historical preparation artifacts, **not a standalone public HTML rebuild recipe**. They reference original source hashes and predecessor sibling inputs; some write output or attempt browser rendering. Do not run them against the preserved public archive to regenerate historical evidence. This export did not run those scripts, mathematical numerical experiments, sampling, model initialization or training.

Both HTMLs are readable offline compositions. Their inherited source-hash tables describe the original preparation. Current exported file identities are in `PUBLIC_SOURCE_MAP.json`. No browser visual PASS is claimed.
