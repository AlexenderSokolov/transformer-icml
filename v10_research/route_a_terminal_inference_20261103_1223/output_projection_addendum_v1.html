Numerical output and memory clarification for Route A v1

2026-11-03. Additive correction to route_a_terminal_report_v1.html, preserved unchanged. Status: provisional candidate; independent full architecture review remains in progress. This is not a numerical-certification or novelty claim.

Project the implemented output after its last numerical error

Let p be the ideal final clipped network output in [0,1] and let the actual pre-projection output p̃ satisfy |p̃−p|≤ζ on every path. The implemented probability output must be p_num=clip(p̃,0,1), with vector (1−p_num,p_num). Projection is nonexpansive, so |p_num−p|≤ζ, and the total risk bound and its additive ζ term remain valid. This final saturation is an explicit additional implementation operation. Without the guarantee that the output lies in [0,1], the use of TV≤1 on bad occupancy or martingale events is unjustified. Applying this correction does not require changing any other displayed constant.

Memory scope

The O(N) claim is token-state/inference storage for a streaming or layerwise executor. It excludes retaining all O(NK) intermediate FFN activations for training/backpropagation. The O(K) stored spline parameters, O(NK) tokenwise arithmetic, masks and positional metadata must be counted separately. A conventional dense attention executor may additionally spend O(N²) operations or memory, depending on implementation.

A distinct agent independently identified these qualifications while reviewing the shared v1; the independent report and any later findings will be stored separately. Exact-real weights, softmax arithmetic and the declared error-port assumptions remain as in v1, not a complete fixed-bit implementation.
