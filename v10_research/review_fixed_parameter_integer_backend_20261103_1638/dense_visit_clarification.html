Clarification: Θ(L²) visits are algorithm-specific

3 November 2026. This note binds to deterministic integer backend v1, SHA-256 962ca335827e4366855a4229798b92ae910c0b3a1996a7b990193757befa98cc.

The straightforward evaluator explicitly scans all causal keys j≤i in each of six active head instances and at every row i=1,…,L. One scan visits exactly 6Σi=1Li=3L(L+1) head/key pairs; two full scans, e.g. one to obtain the maximum and one to accumulate, give 6L(L+1) visits. Both are Θ(L²). The precise constant depends on how the passes are implemented. With the documented O(log L)-bit arithmetic and grade-school operations, this straightforward implementation has the stated O(L²(log L)²+(log L)³) bit-operation upper bound, under the accounting assumptions in the review.

This is a count for the specified all-rows dense schedule, not an unconditional lower bound on every exact algorithm. Special structure in the logits, truncation, or an algorithm that computes only outputs needed at the terminal position might change the work. No improved asymptotic algorithm is claimed or proved here. Six active instances are not a claim that each query has six active heads: two are in block 1 and four in block 3; block 2 has none.

Proposed replacement: “A straightforward full-causal evaluation of the six active head instances visits Θ(L²) query-key pairs; this is an upper-bound accounting for that evaluator, not a lower bound for all algorithms.”
