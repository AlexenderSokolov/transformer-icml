# Independent audit: four-counter half-pooling DP

3 November 2026. Reviewed `RESEARCH_NOTE.md` SHA-256 `94726e5d5d8fd8c938fc4e7a40a7e7a1c660ba9904910663a49cbf0560162b66`, `four_counter.py`, `verify.py`, and the additive correction. The theoretical integer-bank recurrence and its stated asymptotic upper bounds are correct for the fixed-half selected-row interface. The implementation has a material exact-utility limitation described below. This is not a solver for the learned-pooling pilot models.

## Proof and implementation

For M≥2, protected u=(h_M,h_(M+1)), L=floor(M/2) and R=M−L, the four integers (J,C1,D,E) count selected-row transitions, selected successor ones, first-half selected transitions and first-half selected successor ones. They reconstruct the six pilot rails as ((J−C1)/M,C1/M,(D−E)/L,E/L,(J−D−C1+E)/R,(C1−E)/R), followed by the two protected endpoint bits and 1/M. This matches the actual `pilot.Model(mode='half')` input order. C1 is not necessarily the earlier designated-successor count: if the first endpoint bit is 1, it is J minus that count. Learned position weights generally cannot be reconstructed from these four counters.

Both initial bits are editable because M≥2. Each later bit is editable iff t<M and otherwise fixed. Appending z_t completes departure i=t−2, with first-half status i<L. The state consists of the last pair and four counters. Keeping its minimum prefix cost is valid for an **at-most-k** budget: every shared continuation has identical future increments and mismatch costs. It need not be valid for an exactly-k requirement. At most 4(M+1)^4 states per layer and two next bits give O(M^4) rolling states, O(M^5) transitions and O(M^4) terminal readout evaluations. Full predecessor retention, or prefix recomputation, yields the stated memory/time upper bounds; outputting a witness for *every* bank adds output-sensitive cost.

The bank map and integer costs are exact. The theoretical exact-utility statement requires exact rational rails or integer-count-based exact utility and exact comparison. `model_inputs()` actually uses Python float division. At M=3, h=00000, k=1, and the exact-rational utility 1{x0=1/3}, legal z=01000 has exact score 1, but `maximize` receives binary-float x0, fails the Fraction comparison and returns 00000 with score 0. `float_counterexample.py` reproduces this without random operations. The author's ADDITIVE_CORRECTION.md accurately discloses that an exact comparator cannot undo lost rational precision. Floating neural/tanh/cross-entropy outputs further require a numerical comparison/tie analysis. Thus do not describe the current generic `maximize` as an exact rational or exact real neural oracle.

## Verification and boundaries

I independently constructed the brute-force counts and checked every word/edit mask for M=2 through 6, every budget, the full bank/minimum-cost map, all 27,576 returned witnesses, and 3,056 objective comparisons. All 21,824 cached pilot input vectors matched the theoretical reconstructed rails within maximum absolute floating discrepancy 1.12e-16. The original manifest's four hashes pass; its additive correction separately supplies the originally omitted hash of the imported pilot module. The original author's verifier used five model initializations at seed 123; my independent script used five at seed 203. Their generated random weight values were not saved; see `ADDITIONAL_PRESERVATION_AUDIT.md` in the benchmark review directory.

For a fixed h and bank-dependent f, a clean-history target B(h) or permitted p-hat defines a source- and label-blind attack objective. Neither realized Y nor hidden theta may enter attack choice. For exact-real optimization, the utility values and comparisons must be exact; for numerical outputs, report a floating-point result. The gate benchmark uses a different three-counter Q gate, not this four-counter half-model solver. Neither analysis says an arbitrary learned-profile readout depends only on these counters.

Code and deterministic float counterexample are in this review directory. The sampled model-weight omission is separately disclosed; no new random operation was performed after the stop instruction.
