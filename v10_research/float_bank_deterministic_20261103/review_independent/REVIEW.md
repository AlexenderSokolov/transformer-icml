It also gives identical **full eight-triple histograms in each half**: first half (0,0,0,0,0,0,0,512) and second half (0,0,0,2,0,2,2,507). Thus this example defeats a claim that either the four-counter bank or the full-half triple histograms alone determine the actual floating evaluation in the specified invocation. ## Fallback, precision and provenance

For fixed deterministic weights, target, environment and a fully specified batch layout, exhaustive enumeration of N=Σ_(j=0)^k binom(M,j) legal masks followed by evaluation and float comparison can return the maximum of the **computed** finite scores under an explicit NaN/infinity/tie rule, assuming the backend is deterministic. If each candidate occupies a designated slot in a B-row batch with fixed fillers, O(NBM) pooling work and O(BM) working input/intermediate storage are reasonable fixed-architecture bounds; add batched readout, transcendental, comparison, actual allocation and witness/output costs. This protocol need not be bit-identical to a single all-candidate batch. A full N-row invocation uses O(NM) input/intermediate storage and matches only that defined invocation. Neither option certifies an exact-real or transcendental argmax.

The proposed smaller accumulator-state DP remains conditional on a proved backend-specific state transition and layout; no polynomial exact-float DP is established. For bit-precise resource accounting it must also charge at least O(log(M+1)) bits per stored edit cost, along with the accumulator patterns, window, any live reduction state, indexing and backpointers. The note's record/word-level shorthand should not be interpreted as a complete bit-storage bound.
