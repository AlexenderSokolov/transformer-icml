Exact count rounding for the uniform value bank

This immutable addendum concerns uniform_head_bank_v1.html, SHA-256 57671e10c5cac0a6f8bf19e0c678a766d59ca69cfee1b3d95dfb36b96cbe0cb2. Its bound η=O(M−3/2) is sufficient for the direct Lipschitz ratio route, but is not necessary for the count-bank interface.

If M is known and all eight uniform-head outputs u_r,v_r are known to absolute error η<1/[2(M+1)], then (M+1)u_r=C_r+1 and (M+1)v_r=J_r+2 are integers. Multiply each measured value by M+1 using separately paid exact arithmetic and round to the nearest integer. Every count is recovered exactly because its error is strictly below 1/2. Select the actual terminal row and compute the add-one ratio, with output division/rounding charged separately.

This stronger sufficient route uses O(log(M+1)) fractional bits at the bank boundary and applies even when the true query count is zero. It relies on the exact normalized-bank identity, known M, sufficient arithmetic and an explicit discontinuous rounding/readout operation. It is not an end-to-end finite-precision standard-Transformer implementation, or a general precision lower bound.
