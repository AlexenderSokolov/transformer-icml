Correction: precision tie boundary

This correction supplements route_b_terminal_identifiability_v1.html, SHA-256 b557994fb9ee0c6cb2ff87ea26980c049d4b94cc65b66c82264c92ac4199a368. Its §3 sentence “At equality no tie rule guarantees correct decoding” is too broad when the decoder can use the already exact J and C ports.

The strict inequality Mρ(β)ε<1/2 remains a valid, simple sufficient condition for nearest-integer margin decoding. At equality in this coarse worst-case bound, an actual half-integer reconstruction can only occur when D=M exp(|β|). If β>0 this forces every history coordinate to match, and the true matching successor count equals the already known C. If β<0 it forces every history coordinate not to match, and that count is zero. These boundary cases can be resolved by inspecting J and C; when D is strictly smaller, the actual error is strictly below 1/2. Thus a tie rule using the declared exact side information can resolve this boundary, and no impossibility of tie recovery should be inferred. This correction does not assert that arbitrary coarser precision or errors in J and C are harmless.
