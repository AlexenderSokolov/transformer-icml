# Sealed feasibility microbenchmark protocol

Fixed before benchmark generation and measurement, 2026-11-03. Exploratory local timing, not preregistration, population inference, model training or a broad robustness evaluation. The original position-pilot training proposal code is imported unchanged; its fixed-half model requires four selected-row counts (first-half successor-1 count in addition to J,C,D) and is not claimed solved by this three-counter experiment.

Predictor: exact selected-row gated output A_1(z) for probability of 1: if J>0 and 512D>=J, C1/J, otherwise first bit of protected terminal pair; then Q(z)=(1-2/sqrt(M))*A_1(z)+1/sqrt(M). This is the pilot's `statistics()['Q']`. Attack utility: CE(B(h),Q(z)), B(h)=(C1(h)+1)/(J(h)+2). The target is frozen from CLEAN h before attacking; no latent source parameter or held-out label is supplied to either attack. This is the pilot's clean-B history-only surrogate, not true-source loss and not optimization of a learned predictor. If eps smoothing leads to equal extremes, exact tie policy is arbitrary deterministic.

Compare exact reachable-state DP with the union of the original training and heldout block/equispaced proposal families, each using the same clean h, at-most-k edits of first M symbols, same protected terminal pair, exact fixed Q, and same CE. DP retains minimum cost per (last pair,J,C1,D) and parent pointers to reconstruct a feasible maximizer. Compare objective values and verify every witness independently with the original pilot implementation. The exact DP is allowed all legal edits, while proposals form a subset; this is not an equal computation-budget comparison. Record wall time, process CPU, peak resident memory and both comparison family sizes; Python/NumPy proposal timing includes its own overhead and is not a platform-neutral throughput comparison. Cap DP at 300,000 live states, 3,000,000 accumulated nodes, and 10 seconds elapsed per case; record noncompletion without imputation. A cap is checked within each state loop. Do not tune after results.

Cases: M in [16,32,64,128], k in [1,2,4], 3 histories per horizon drawn with numpy RNG seed 845120. Independently choose start pair uniformly and generate each history under three fixed binary order-2 tables [0.5,0.5,0.5,0.5], [0.15,0.5,0.5,0.85], [0.03,0.5,0.5,0.97]. The table index orders the histories; it is used only for data generation. All actual words are saved; attack interfaces receive no table or target label. Use compiled standard C++ (g++ -O2 -std=c++17), single-thread NumPy (environment pinned in runner), same executable across all cases; save code hash and compiler/system description. Run one case once in fixed order; timings are descriptive and subject to OS noise. Baseline proposal runtime and output for capped exact cases remain recorded.

Before benchmark, run independent tests: Python exhaustive edited-mask oracle against DP for all words at M=4, k=0..4; separate random deterministic cases M=5..8 and budgets 0..3. Validate clean and attacked J,C,D,Q, CE and objective, protected endpoint, edit budget, existence of exact witness and maximum among all legal words, as well as original candidate family inclusion. Tests and all cases must be saved as machine-readable raw records. Do not run pilot if tests fail. No modifications of previous units.

Pre-run clarification: after each attack has selected and returned its witness, the evaluation harness may read the fixed generating table and report absolute probability error |Q(z)-theta_terminal(1)| as a descriptive held-out, source-aware diagnostic. It must not feed theta or these scores back into candidate selection, ties, protocols or model choice. The same post-selection score is computed for clean input and both selected attacks. Because the proposal and exact surrogate objectives select different attacks, higher CE need not imply higher source-TV. The generating tables and actual words will be saved with the results; they are not passed to the attack function.
